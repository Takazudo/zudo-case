## 最初のコマンド

まずzipを展開し、その中の`apply-overlay.py`を使います。既存ファイルは上書きしません。

```sh

# 内容・パスを確認後:
python /path/to/zudo-case-fitfix-01/apply-overlay.py /path/to/zudo-case --apply

cd /path/to/zudo-case/engineering/r9-fitfix-01
uv run --locked --project ../r9-prototype-01 python build.py
```

## 統合方針

`engineering/r9-fitfix-01`を独立した候補版として取り込む方法を推奨します。R9-PROTOTYPE-01の出力/台帳は履歴へ残し、同じ版名のまま差し替えません。別の候補名へ改名して取り込む場合は、ファイル・manifest・プレビュー・台帳の版を一括で合わせてください。

このコードの本体参照は、現在R9も継承している**保存R6の公称部品**を読み取り専用で再構築します。36本の長穴を含む本体５枚はR9の穴ルールで再作成しています。ローカルでは比較ツールで現行R9のDXF一致を確認し、必要なら本体参照を現在のR9ジェネレーターの実Part/配置インスタンスに置き換えてください。再構成した金具と実物の形が一致すると保証したものではありません。

1. 固定環境で生成し、修正前R9と新候補の本体３パターンを比較する。
2. 生成コードをレビューし、ガード主要部の実肉厚、屋根の直接着座、側面接着空間の解釈を確認する。
3. 新候補ディレクトリを読み込めるよう、`sync-r9-ledger`等のR9固定パスをパラメータ化、または新候補専用の入口へ分離する。古いR9のmanifestへ新しいhashだけを入れない。
4. 確認後の`tools/make_ledger_proposal.py --after-local-verification`をJSONへ保存し、candidate_filesの追加・蓋の現行候補指定に使う。候補と製造承認を混同しない。
5. docsの生成表/比較/BOM/プレビューの参照を新候補へ統一。publicのコピー後に公開資産ハッシュとサイズを検査し、旧画像との混在を防ぐ。
6. 既存CIのdocs/tables/ledger/assets/type/build/preview確認に加え、新しい11回帰テストと全体CAD生成を実行する。
7. ローカルで検証した新候補のoutを必要なファイルに絞ってGitへ追加し、コード差分と固定環境の結果をGitHubへ反映し、#99〜#101のコード課題としての完了可否を判断。G03/G04等の現物結果は別のまま。

## 重要な設計判断

**今回の支持面は金属との直接接触です。** 上端ガードの屋根下面はZ=91、本体上端へ載り、その屋根上面Z=92.2が蓋の座面です。以前の「全高93.4を上端Zと見なす」「蓋が0.5浮く」状態をなくしました。

側面の0.30mmの空きは、fit0.15＋adhesive0.15という候補配分です。これは「0.15mmテープを貼ればそのまま全て埋まる」という意味ではありません。実空間を充填して保持できる接着剤、またはテープ/当て材を選び、実測・試験で調整してください。上面/底面へ追加のテープを入れる場合はハードストップの高さが変わるため、パラメータとモデルを修正します。

**幅・奥行が各0.6mm増えます。** 金属本体寸法は変えず、外側ガードが片面0.3mm外へ増え、内側返しも実肉厚を確保します。蓋天板は基本案228.2×332.8×1.5mmです。1.0mm案の専用天板は227.8×332.4×1.5mmです。

部品を厚い旧形状へ戻す変更ではありません。基本案のガード総体積は約39.235cm³、蓋PA12枠は約84.378cm³です。価格は未取得。過去の2,264円は現在見積ではありません。

## パッチ適用時の補足

`changes.patch`は16ファイルを新規追加するsource-only差分です。`git apply`時にベンダーThree.jsのGLSL文字列について末尾空白の警告が出ることがあります。元のライブラリ表現を保存しており、通常の適用は成功します。`apply-overlay.py`を使う場合はパッチも続けて適用しないでください。
