# R5 3MF import compatibility repair

## Confirmed cause

The original generated projects were valid ZIP files with namespace-correct
XML, but their root relationship file used the lexical element name
`ns0:Relationship`. The Bambu Studio importer examined here does not enable
Expat namespace processing. It compares the incoming raw name with the
literal `Relationship`. As a result, the prefixed relationship was ignored,
the main model path remained empty, and loading returned false before reading
the model. This affected all 15 current and all 14 frozen R4 input archives.

The original saved H2D template used unprefixed relationship tags. The change
was introduced when the helper removed stale thumbnail relationships and
reserialized that document with ElementTree's generic namespace prefixes.
The previous namespace-aware verifier accepted equivalent XML names and
therefore failed to reproduce this importer limitation.

## Evidence in the official source

Pinned Bambu Studio commit:
`4c2c19a4bf698edf153555dfe28fd4f81d6550be`.

[bbs_3mf.cpp](https://github.com/bambulab/BambuStudio/blob/4c2c19a4bf698edf153555dfe28fd4f81d6550be/src/libslic3r/Format/bbs_3mf.cpp)
provides the relevant behavior:

- Line 2916 creates the XML parser without namespace processing.
- Lines 5555–5556 compare the raw element name and dispatch relationship parsing.
- Lines 5574–5580 recognize a model relationship and set the main model path.
- Lines 2137–2140 load root relationships and return false if that path is empty.
- Lines 3907–3946 dispatch model tags using the same exact-name comparisons.
- Lines 4001–4040 dispatch model-configuration tags.
- Lines 4176–4178 recognize `p:UUID` and `p:uuid` attribute names.

The new `verify_studio_import_contract.py` uses Python's Expat binding in the
same namespace mode and reproduces the relevant exact tag dispatch. It
recognizes no model target in the original files and recognizes
`/3D/3dmodel.model` in the repaired files. It checks other current XML surfaces
for the same lexical-name problem, plus model/configuration references,
UUID bindings, content-type declarations, and saved filament settings.

## Change and preservation

Only `_rels/.rels` changed inside each corrected archive. Its relationships
and targets have the same namespace-aware meaning; the element names now
remain unprefixed under the default OPC namespace. Every model/mesh/build,
object/plate configuration, and global project-settings payload is unchanged.
No geometry, printer reach, material, nozzle mapping, or print pose was changed.

`tools/bambu_3mf.py` now serializes OPC relationship/content-type documents
without autogenerated element prefixes. It does this per document without
changing the global namespace registry, so core model serialization still
uses the correct unprefixed names. Its validation also checks that the raw
relationship dispatcher can find the main model.

The original files are preserved outside the current delivery set as repair
evidence. `import-repair-report.json` records their hashes and the repaired
hashes, with the changed-member list for each current and frozen archive.
The 14 frozen input archives are no longer byte-identical to the old R4
archives; their geometry and settings payloads remain byte-identical.

## Verification limits

The corrected set passes the focused import contract, package/mesh/layout
checks, and an isolated rebuild from the corrected bundled inputs. A separate
review found no second tag-prefix or reference error in the current model and
configuration surfaces. No Bambu Studio executable was available to perform
an application load or slice, so those checks remain pending. The source-based
verifier is not a replacement implementation of the entire Studio importer.
