このページが、人とエージェントの共通の編集方針です。対象はケースを選ぶ人、現行ファイルで印刷・組立を準備する人、設計の根拠を確認する人、サイトと台帳を保守する人です。現行手順から目的を達成できるようにし、旧版の開発経緯を順に読まないと作業できない構成にしません。

## 文書を書くルール

日本語MDXを`src/content/docs/`へ置きます。各カテゴリに短い`index.mdx`を作り、全ページに`title`・`description`・数値の`sidebar_position`を指定します。順番は同じ親で重複させません。カテゴリの`index.mdx`の値は親の兄弟との並び順です。本文にH1を加えず、見出しは`##`から始めます。文書間リンクは相対`.mdx`、公開資産は`/images`などの公開パスを使います。

新しいページ、既存ページへの新しい作業・話題の追加、ページの役割変更には、次の４点を確認します。誤字・表現・書式だけの修正は省略できます。

1. 誰が、この内容を使って何をできるようになるか。
2. 同じ役割のページが既にないか。タイトル、description、カテゴリ一覧を検索し、draft・unlistedも重複候補として確認する。
3. どのカテゴリが所有するか。競合する置き場所と、次の境界表で決め手になる違いは何か。
4. 追加によってカテゴリの意味が変わるか。

答えが明確なら配置し、PRまたは作業記録へ理由を１行残します。日常の配置理由をこの方針へ蓄積する必要はありません。

## カテゴリの意味と境界

以下は確定した**編集上の決定**です。仕様の採用・寸法の測定・製作承認とは別です。正式なページは８区分のどれか１つが所有します。７つの現行区分は各系列の最新の状態だけを持ち、置き換わった読み物は`archive/`が所有します（次の「現行とアーカイブ」）。

| 区分 | 読者と作業・含む内容 | 含めない内容・隣との境界 |
|---|---|---|
| `overview/` | ケースを選ぶ人の入口、系列をまたぐ短い状態要約、共通の用語 | 版別の印刷手順・数量・詳しい設計根拠は各系列へ。全体案内からリンクする |
| `metal-case/` | 金属ケースを準備する人の３機種の現行版（7U40はR11-BUILD-FEEDBACK-04、3U60・7U60はR6本体＋R8載せ蓋の基準）、見積、発注前確認、金属台帳保守 | R10・R9以前の7U40候補と旧手順は`archive/metal-case/`。家庭印刷や10BOX-v2の仕様は含めない。「10BOX式の載せ蓋」という方式名だけで10BOX-v2へ分類しない |
| `printed-5mm/` | 7U40・5mm家庭印刷の現行P5の設計・プレビュー・ファイル・通気孔 | 旧P4/P3は`archive/printed-5mm/`。独立した二段3U60HPの10BOX-v2、金属の数量・発注記録は含めない |
| `tenbox-v2/` | 二段3U60HPの独立10BOX-v2。最新版R8の印刷、組立、ファイル、設計根拠と検証限界 | 10BOX-v2全体が試作・改良中。旧R5の読み物は`archive/tenbox-v2/`。7U40のP5改訂ではない |
| `two-way/` | 2トレーの検討を読む人のTW-01作業版（A/B/Cはどれも現行の比較対象）と、その入力であるF5原資料の参照 | 製造用CADや単トレーの蓋仕様を置き換えない。F5は競合する現行版ではない |
| `shared/` | 複数系列が参照する部品・元レール・PCB・出典 | 一系列だけの部品数量や採用値は系列側。部品が似ているだけで共通仕様にしない |
| `development/` | サイトを起動・保守する人の環境、文書編集方針、生成所有と旧URL、配信の仕組み | 金属だけの見積・承認台帳は[金属台帳保守](../metal-case/maintaining-data.mdx)へ。CAD作業は系列のengineeringへ。現在の作業に使わない監査・移行の経緯はアーカイブへ |
| `archive/` | 置き換わった旧版を読む人の、系列ごとの設計・発注準備・検証・判断の記録 | 現行の手順・数量・ファイル案内を置かない。現行版の生成に使う入力（10BOX-v2のR4固定入力、2WAYのF5、共通のレール・PCB）は古くてもアーカイブにしない |

## 現行とアーカイブ

**ライフサイクルの決定（2026-11-22のユーザー指示）:** 通常の文書と探し方（メニュー、サイドバー、カテゴリ一覧、前後リンク、全体案内、現行プレビュー、ダウンロード一覧、BOM・比較表、プレビュー配信元の入口、既定の検索）は、各系列の最新の状態だけを示します。旧版の開発経緯を読まなくても現行の手順で作業できるようにします。これにより、旧版を現行の系列ナビゲーションに並べて見せていた以前の方針を置き換えます。

- 現行版は系列・機種・用途ごとに`project/current-selection.json`で指定します。最大の版番号や新しい日付では選びません。数値・数量は各系列の台帳が持ち、この表は参照だけです。指定は製造承認ではありません。
- 置き換わった読み物は`archive/<系列>/`へ移します。各アーカイブページの先頭に、履歴であることと現行の置き換え先へのリンクを示す注意書きを置きます。旧版のページへ現行の数量や価格を書き足しません。
- 旧版と現行が混ざったページは、現行の内容だけで完結するように書き直し、旧版の説明をアーカイブへ分けます。現行の手順を理解するのに必要な設計理由は現行ページに残します。旧表を現行の説明の下に並べる、折り畳む、といった方法では分離になりません。
- 既定の検索はzudo-doc 10.0.3の`search_exclude: true`でアーカイブの個別ページを除きます。入口の`archive/index.mdx`と`archive/<系列>/index.mdx`は検索に残し、アーカイブ全体はそこから閲覧できます。`unlisted`は旧URLの互換ページ専用で、アーカイブには使いません。
- 前後リンクはzudo-docが最上位区分ごとに解決するため、`archive/`は現行区分の順番に入りません。`pnpm check:built-doc-routes`がこれと検索の扱いを検査します。
- 旧版のプレビュー・ダウンロードは元のURLとバイト列のまま残し、リンクはアーカイブのページへ移します。生成に使う依存ファイルを移動・削除しません。
- 履歴がない系列に空のアーカイブ章を作りません。現行版の入力として使う古いファイル（10BOX-v2のR4、2WAYのF5、共通のレール・PCB）は、古いことを理由にアーカイブへ移しません。

## 構成を見直す条件

カテゴリ競合、同じ読者作業の重複、既存の定義と異なる独立した内容群、読者が目的のページを見つけられない具体的な報告がある場合に見直します。ページ数、均等さ、点数だけを理由に再編しません。

まずカテゴリ一覧とこの方針を読み、関係・競合するページと例外だけを順に確認します。調べた範囲を作業記録へ示し、部分調査を全体監査と呼びません。読者の困りごとを１〜２文で書き、既存ページへの追記、見出し・入口の改善、局所的な分割・統合、主たる置き場所と関連リンクを比較します。問題を解決できる案から選び、同等なら変更量を比較します。構成維持も有効な結論です。同じ入力を新しい根拠なしに再分類しません。

後続の著者に必要な境界、重要な例外、実施した再編の理由だけをここへ残します。所有者の決定、設定・既存文書で確認できる事実、未確認の仮説を区別し、空欄や推測を確定ルールにしません。既存方針で解けない重要な目標の衝突だけを所有者へ確認します。

## ナビゲーションとURLの例外

通常はファイルシステムの階層と、リンク先を持つカテゴリの行をそのまま使います。ヘッダーの「ケース」は全体案内への入口で、金属・7U40家庭印刷・10BOX-v2・2WAYを選べます。これはヘッダーだけのグループで、サイドバーに架空の親は作りません。行き先の所有はURL先頭と固有の`categoryMatch`で決まります。

`overview`・`metal-case`・`tenbox-v2`・`two-way`・`shared`・`development`は`src/sidebars.js`の`items: []`と`scopeRoot: "configured"`で、その系列の実際の根を上限にします。初回表示とRestoreは系列全体、Broadenはそこを越えません。短い平坦な区分に狭い`initialPath`を足しません。

**家庭印刷の編集ツリー（決定）:** `printed-5mm`の現行ページは平坦なURLのまま、`src/navigation/printed-tree.js`の編集ツリーでリンク付きの入口の下に現行P5設計を置き、その下にプレビュー・ファイル・通気孔を置きます。旧P4/P3は現行ツリーに含めず、`archive/printed-5mm/`の通常の区分として表示します。ページ追加時はメンバー表にも加え、正式ページがちょうど１回ずつ現れることを検査します。

この例外は同じコンテキストを渡すHeader/Sidebarの組だけを変更します。パンくず、前後リンク、検索、sitemap、`CategoryNav`はURLベースのままです。したがって家庭印刷の入口と設計ページは編集ツリーと同じ順のリンクを本文へ明示します。通常の一覧は標準`CategoryNav`を使い、互換ページの残るディレクトリは`categories={[...]}`で正式な子だけを列挙します。

## ページを移動するとき

既存の公開URLと見出しアンカーは保持します。論理上の分類とファイル移動によるURL変更を別々に判断します。`project/doc-routes.json`へ所有区分・正式なページ・旧ページ・扱いを記録し、`node scripts/sync-doc-routes.mjs`で`unlisted: true`互換ページと[所有表](./doc-structure.mdx)を生成します。新規ページは`source: null`で追加し、正式行を重複させません。

`source`は2026-11-06の再編前の基準URL（`baseline.documents`件）で、その数は別の不変条件として検査します。その後に移動したページの旧URLは、同じ正式行の`aliases`へ`path`・`anchors`（必要なら`anchorTargets`）で加えます。基準URLもaliasesも、すべて最終的な正式ページへ直接リンクします。互換ページから別の互換ページへつなぐ連鎖や、同じページを２行で所有することはできません。`compatibilityRoutes()`が生成・ソース検査・所有表・ビルド後の検査で共通に使う列挙です。

互換ページを手で編集せず、旧見出しアンカーを残し、内部リンクは正式ページへ向けます。互換ページはルートとして存在しますがサイドバー・検索・前後リンクから除外します。言語・版の追加や移動は`zfb.config.ts`の`docsDir`・locale設定を確認して別に扱い、版スナップショットを現在文書と一緒に再編しません。

## 数字の更新

金属の表と製作・見積台帳の更新手順は[金属ケースの台帳・製作データを保守する](../metal-case/maintaining-data.mdx#数字の更新)へ移しました。金属用`project/current-spec.json`を他系列の仕様に流用しません。10BOX-v2の現行指定は`project/tenbox-v2/current.json`、R8の数値・数量・出力と検証は`project/tenbox-v2/r8-review.json`を参照します。R5の`manifest.json`と版別README・ZIP内の状態表示は生成当時の記録として保全し、現行指定の根拠には使いません。7U40家庭印刷と2WAYは各系列の台帳を参照します。

## 生成物の所有

| 対象 | 編集元・再生成コマンド |
|---|---|
| 旧URL互換ページ・文書所有表 | `project/doc-routes.json` → `node scripts/sync-doc-routes.mjs` |
| 金属３機種・比較・BOMの現行ページと旧7U40表のアーカイブ | `project/current-spec.json`（7U40はR11の台帳） → `node scripts/sync-reference-tables.mjs` |
| 金属7U40 R11-04の取込み・公開コピー・現行指定 | `engineering/r11-build-feedback-04/` → `node scripts/sync-r11.mjs` |
| 金属R9の版・ファイル表（アーカイブ） | 対応する台帳 → `node scripts/sync-r9-doc-table.mjs` |
| 金属R10のZIP・座金表（アーカイブ）と旧来の`current_fullset_candidate`（R10の記録） | 対応する一式台帳 → `node scripts/sync-fullset.mjs`。現行指定`current_metal_7u40_candidate`には書き込まない |
| プレビュー配信元の入口 | `project/current-selection.json` → `node scripts/prepare-worker-assets.mjs` |
| 系列ごとのCAD・パッケージ・プレビュー | 各`engineering/*/AGENTS.md`・README・版付きソースと検証手順 |

生成対象は直接編集せず、ソースまたは設定を変えて再生成します。元ソース、受領ZIP、元マニフェストは不変の根拠として保全します。台帳はCADジェネレーターの入力と同義ではありません。数値の更新だけで形状・製作ファイル・検証・承認が更新されたとは記載しません。

## リンク・資産を確認する

```sh
pnpm check:docs
pnpm check:doc-routes
pnpm test:doc-structure
pnpm check:tables
pnpm check:r11
pnpm check:assets
pnpm test:setup
pnpm check
pnpm build
pnpm check:built-doc-routes
pnpm check:built-preview-links
pnpm check:images
```

該当系列と変更箇所の追加検査も実行し、実行コマンドと観測した結果を記録します。未実行を合格にしません。静的整合、MDXビルド、実ブラウザー、CAD形状、実スライス、現物嵌合・荷重は異なる確認です。表示変更はdesktopと390pxの実ブラウザーで、キーボード／メニュー／Restore／Broaden／系列の所有、既定の検索と前後リンクが現行だけを示すこと、アーカイブと旧URLへの到達を確かめます。

ハッシュ検査で元データとの差を見つけたら、旧版を保全して新版の根拠・入力出力ハッシュを対応する台帳へ追加します。期待ハッシュの上書きだけで検査を通しません。配信・起動・復旧の詳細は[起動と保守](./setup.mdx)、過去のブラウザー記録はリポジトリの`project/browser-validation.md`を参照してください。

## 過去版の見せ方

旧版は[現行とアーカイブ](#現行とアーカイブ)のとおりアーカイブだけで見せ、版と状態を明示します。旧アーカイブは削除せず、旧ロック蓋や旧一式を最新と呼びません。価格は対象版と条件を保って履歴に残します。文書更新日、CAD改訂日、業者見積日、実測日を区別し、分からない過去発言へ日付を推測しません。

## 見積・製作データの状態を進める

金属だけの登録・採用・承認台帳は[金属ケースの手順](../metal-case/maintaining-data.mdx#見積・製作データの状態を進める)を参照してください。候補の登録、ソフトウェア検査、プレビュー表示は製造承認を意味しません。全系列の`production_approved`は`false`を保持し、注文・価格採用・現物確認を文書整理から推定しません。
